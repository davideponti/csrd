# Step 22-23: Export Multi-Formato & Web Scraper Regolatorio EU

## Step 22: Export Multi-Formato

### Obiettivo
Implementare un sistema di export che permetta di esportare i report CSRD in 5 formati diversi:
1. **iXBRL (XHTML)** — formato principale per filing regolatorio ESMA/ESAP
2. **PDF** — per stampa e condivisione interna
3. **XLSX** — per analisi dati strutturati
4. **Word (DOCX)** — per bozze e revisioni
5. **JSON** — per integrazione API

### File creati/modificati

| File | Descrizione |
|------|------------|
| `backend/app/services/export_service.py` | **NUOVO** — Servizio di export multi-formato |
| `backend/app/api/reports.py` | **MODIFICATO** — Aggiunti endpoint di export |
| `backend/requirements.txt` | **MODIFICATO** — Aggiunte dipendenze export |
| `frontend/src/app/reports/page.tsx` | **MODIFICATO** — UI export con pulsanti download |

### Architettura ExportService

```
ExportService
├── export_pdf()        → xhtml2pdf / ReportLab (fallback)
│   ├── _generate_fallback_pdf()
│   └── _generate_minimal_pdf()
├── export_xlsx()       → openpyxl
│   ├── Foglio Summary
│   ├── Foglio GHG Emissions
│   ├── Foglio Materiality
│   └── Foglio ESRS Coverage
├── export_docx()       → python-docx
│   ├── XHTML → DOCX parsing
│   └── Tabelle strutturate
├── export_json()       → json.dumps()
│   └── Serializzatore custom
├── export_ixbrl()      → Pass-through
└── export_all()        → Export completo 5 formati
```

### Data Classes
- `ExportOptions`: opzioni comuni (watermark, margini, lingua, etc.)
- `ExportResult`: risultato standardizzato (content, mime_type, size, etc.)

### Fallback Strategy
Per PDF, se xhtml2pdf non è installato:
1. **Primo fallback**: ReportLab — genera PDF con formattazione base
2. **Secondo fallback**: PDF minimale con solo testo — generato manualmente senza dipendenze

### API Endpoints
- `GET /api/v1/reports/{id}/export/{format}` — Scarica report in formato specifico
- `POST /api/v1/reports/{id}/export-all` — Export in tutti i formati (metadata)
- `GET /api/v1/reports/export/formats` — Lista formati disponibili

## Step 23: Web Scraper Regolatorio EU

### Obiettivo
Creare un sistema automatico di monitoraggio normativo che raccolga documenti e aggiornamenti da fonti ufficiali EU relative a CSRD/ESRS.

### Fonti monitorate

| Fonte | URL | Tipo | Frequenza |
|-------|-----|------|-----------|
| EUR-Lex | eur-lex.europa.eu | EU Law | 6h |
| EFRAG | efrag.org | Standard Setter | 12h |
| ESMA | esma.europa.eu | Regulator | 12h |
| CONSOB (IT) | consob.it | National | 24h |
| BaFin (DE) | bafin.de | National | 24h |
| AMF (FR) | amf-france.org | National | 24h |

### File creati

| File | Descrizione |
|------|------------|
| `ai-engine/regulatory_intelligence/__init__.py` | **NUOVO** — Package init |
| `ai-engine/regulatory_intelligence/scraper.py` | **NUOVO** — Scraper engine |

### Architettura Scraper

```
RegulatoryScraper (base)
├── EURLexScraper
│   ├── _scrape_sparql()     → API SPARQL EUR-Lex
│   └── _scrape_html_search() → Fallback HTML
├── EFRAGScraper
│   └── 4 sezioni monitorate
├── ESMAScraper
│   └── 3 pagine monitorate
└── NationalAuthorityScraper
    ├── CONSOB (IT)
    ├── BaFin (DE)
    └── AMF (FR)

AsyncHTTPClient
├── Rate limiting per dominio
├── Retry su 429
└── Timeout configurabile
```

### Funzionalità
- **Classificazione automatica**: identifica il regolamento (CSRD, ESRS, EU Taxonomy, etc.)
- **Estrazione standard impattati**: parsing ESRS E1, ESRS S1, etc. dal testo
- **Classificazione impatto**: CRITICAL / MODERATE / INFO
- **Deduplicazione**: hash SHA-256 per evitare documenti duplicati
- **Rate limiting**: rispetta i limiti di richiesta per ogni dominio
- **Sync Wrapper**: versione sincrona per uso non-async
- **Factory pattern**: `create_scraper()` per istanziare scraper specifici

### Usage

```python
# Async
results = await scrape_all_sources(countries=["IT", "DE", "FR"])

# Sync
results = scrape_all_sources_sync(["IT"])

# Singola fonte
result = scrape_source_sync("eurlex")
```
