## Step 28 — Report Generation Pipeline (Frontend + Backend)

### Pipeline di Generazione Report (5 Step)

Il frontend è stato completamente riscritto con un'interfaccia a tab per gestire l'intero lifecycle del report.

**Tabs disponibili:**
1. **Elenco Report** — Lista card dei report con stato, export e azioni rapide
2. **Generazione** — Pipeline a 5 step con progresso visivo
3. **Anteprima** — Preview HTML del report completo
4. **Validazione** — Risultati validazione iXBRL

### Feature Implementate

#### 1. Generation Pipeline UI
- Pulsante "Genera Report [Anno]" che avvia la pipeline sequenziale
- 5 step con indicatore di stato (pending/running/done/error):
  1. Compiling ESRS data — Raccolta dati aziendali
  2. Running gap analysis — Gap analysis dati vs ESRS
  3. Generating narratives — Testi narrativi con AI
  4. Building tables & charts — Tabelle e grafici
  5. Tagging iXBRL — Tagging XBRL per filing regolatorio
- Progress bar orizzontale globale
- Call API reali per ogni step (`POST /reports/{id}/generate`)

#### 2. Review Cycle
- **Submit for Review**: report passa da `draft` → `review`
- **Approve Report**: report passa da `review` → `final`
- Dialog modale per invio in revisione con commenti
- Aggiunta commenti con possibilità di risoluzione
- Badge di stato: Bozza (giallo), In Revisione (blu), Finale (verde), Depositato (default)

#### 3. Preview iFrame
- Anteprima HTML del report generato in iframe sandboxed
- Dati mock GHG (Scope 1, 2, 3) con tabelle ESRS conformi
- Toggle mostra/nascondi anteprima

#### 4. Validation Results
- Dashboard validazione iXBRL: errori (0), warning, total_checks
- Warning dettagliati per datapoint (ambra)
- Statistiche: errori, warning, controlli in card colorate

#### 5. Export Buttons
- 5 formati: PDF, iXBRL, XLSX, DOCX, JSON
- Stato di caricamento per export
- Download automatico via blob URL

## Step 29 — Multitenancy, Subscriptions & Deployment

### 1. Multitenancy (multitenancy.py)

Middleware che gestisce l'isolamento dei dati tra tenant (aziende):

**TenantContext** — Context thread-safe per tenant ID e schema
- `set(tenant_id, schema)` — Imposta contesto per la richiesta
- `get_tenant_id()` / `get_schema()` — Recupero contesto
- `clear()` — Pulizia dopo la risposta

**MultitenancyMiddleware** — Middleware FastAPI che:
1. Estrae il token Bearer dall'Authorization header
2. Decodifica il JWT per ottenere `company_id` e `schema`
3. Imposta il TenantContext per tutta la richiesta
4. Aggiunge header `X-Tenant-ID` alla risposta
5. Pulisce il contesto al termine
6. Path pubblici esclusi (login, register, health, docs)

**Automatic Query Filtering:**
- `apply_tenant_filter(query, model)` — Applica automaticamente `WHERE company_id = :tenant_id`
- `get_current_company(db)` — Dependency per ottenere l'azienda corrente
- `get_tenant_db()` — Session con schema PostgreSQL tenant-specific

**Feature Flags per piano:**
- AI assistant, iXBRL filing, regulatory intelligence
- Multi-user, API access, custom branding, priority support

### 3. Deployment Infrastructure

#### Nginx Reverse Proxy (infrastructure/nginx/default.conf)
- HTTPS redirect (HTTP → 301 HTTPS)
- SSL termination con TLSv1.2/1.3
- Security headers: HSTS, X-Frame-Options, XSS Protection
- Rate limiting: 100 req/min per IP, 500 req/min per tenant
- CORS headers per richieste API cross-origin
- Cache static assets (1 year)
- Backend upstream con least_conn + keepalive
- Health check path: `/health`
- API subdomain: `api.csrdcomply.io`

#### Terraform (infrastructure/terraform/)
- **main.tf** — Risorse DigitalOcean:
  - PostgreSQL 16 managed database (2GB RAM, 1 node)
  - App Platform: Backend (2 instance) + Frontend (2 instance)
  - Spaces bucket per report ed esportazioni
  - Firewall database → solo traffico dall'app
  - Domini: csrdcomply.io + api.csrdcomply.io
- **variables.tf** — Variabili sensibili (DO token, JWT secret, API keys)
- **outputs.tf** — Output: URL, DB connection, bucket names

#### Config Enhancement
- `ENABLE_MULTITENANCY: bool` — Flag per attivare middleware
- `DEFAULT_SCHEMA: str` — Schema PostgreSQL predefinito
- `DEPLOYMENT_DOMAIN: str` — Dominio di deployment
- `DEPLOYMENT_SSL_ENABLED: bool` — SSL flag
