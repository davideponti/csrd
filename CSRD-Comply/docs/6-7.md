# Step 6-7: NLP Parser & Gap Analysis Automatica

## Step 6 — NLP Parser: Mappa Descrizioni ESRS a Domini Aziendali

### Obiettivo
Usare un LLM (GPT-4o / Claude 3.5 Sonnet) per mappare i datapoint ESRS (testo legale) al contesto specifico di un'azienda, determinando applicabilità, fonti dati suggerite e priorità.

### File Coinvolti

| File | Stato | Descrizione |
|------|-------|-------------|
| `ai-engine/esrs_parser/esrs_nlp_mapper.py` | ✅ Aggiornato | Classe `ESmapper` con supporto OpenAI/Anthropic/fallback rule-based |
| `backend/app/api/ai.py` | ✅ **Nuovo** | Router API per ESRS mapper con caching 30gg |
| `backend/app/api/router.py` | ✅ Aggiornato | Incluso router `/ai` |
| `frontend/src/lib/api.ts` | ✅ Aggiornato | Client `ai.*` metodi |

### Architettura

```
POST /api/v1/ai/esrs-mapper
  Input:  { disclosure_text, sector, activities, countries, employee_count }
  Output: { applicable, confidence, data_source_suggestion, difficulty, priority, rationale }

POST /api/v1/ai/esrs-mapper/batch
  Input:  { datapoints: [...<single input>] }  (max 50)
  Output: { results: [...<single output>], total, applicable_count }

GET  /api/v1/ai/esrs-mapper/status
  Output: { cache_size, cache_ttl_days, provider }

POST /api/v1/ai/esrs-mapper/clear-cache
  Output: { status, size }  (admin only)
```

### Cache Strategy
- **In-memory cache** con TTL di **30 giorni** (la tassonomia ESRS non cambia spesso)
- Chiave: `{company_id}:{disclosure_text_truncated}`
- In produzione: sostituire con Redis

### Provider Supportati

| Provider | Modello | Configurazione |
|----------|---------|----------------|
| OpenAI | GPT-4o | `OPENAI_API_KEY` in `.env` |
| Anthropic | Claude 3.5 Sonnet | `ANTHROPIC_API_KEY` in `.env` |
| Fallback | Rule-based | Nessuna dipendenza |

### Rule-based Mapping Euristiche

| Settore NACE | Comportamento |
|-------------|---------------|
| M, N, J, K (Servizi/Ufficio) | Emissioni/GHG rilevanti, Biodiversity escluso |
| C, D, E, F (Manifatturiero) | Alta rilevanza emissioni/rifiuti/energia |
| Employee < 50 | Esclude Scope 3 Cat.15 (investimenti) |

## Step 7 — Gap Analysis Automatica

### Obiettivo
Confrontare i datapoint ESRS obbligatori per l'azienda con i dati già presenti nel sistema e identificare i gap strutturati.

### File Coinvolti

| File | Stato | Descrizione |
|------|-------|-------------|
| `ai-engine/esrs_parser/gap_analyzer.py` | ✅ Aggiornato | Classe `GapAnalyzer` con matching granulare |
| `backend/app/api/assessment.py` | ✅ Esistente | Endpoint `GET /{assessment_id}/gap-analysis` |
| `frontend/src/app/assessment/page.tsx` | ✅ Esistente | Tab "Gap Analysis" con metriche e priority actions |
| `frontend/src/lib/api.ts` | ✅ Aggiornato | Metodo `assessments.getGapAnalysis(id)` |
| `ai-engine/cli.py` | ✅ Esistente | Comando `python cli.py gap-analysis <company_id>` |

### Logica di Analisi

1. **Recupera** tutti i datapoint ESRS obbligatori
2. **Per ogni datapoint**, controlla:
   - **Emissioni/GHG** → controlla tabella `emissions_data`
   - **Materialità/Impact/IRO** → controlla tabella `materiality_scores`
   - **Narrativi/Contesto** → marca come `PARTIAL` (dati parziali)
3. **Classifica**:
   - `COMPLETE`: dato presente e verificato
   - `PARTIAL`: dato presente ma non completo
   - `MISSING`: dato assente
4. **Raggruppa** per standard ESRS (E1, E2, S1, G1...)
5. **Genera priority actions** ordinate per criticalità

### Endpoint API

```
GET /api/v1/assessment/{assessment_id}/gap-analysis
```

### Output

```json
{
  "total_required": 50,
  "complete": 12,
  "partial": 18,
  "missing": 20,
  "completion_percentage": 24.0,
  "gaps_by_standard": {
    "ESRS E1": { "required": 14, "complete": 3, "partial": 5, "missing": 6 },
    "ESRS S1": { "required": 8, "complete": 2, "partial": 3, "missing": 3 }
  },
  "priority_actions": [
    {
      "datapoint": "Gross Scope 1 GHG emissions (tCO2e)",
      "standard_ref": "ESRS E1-4",
      "priority": "critical",
      "effort": "medium",
      "suggestion": "Inserire dati ESRS E1-4: Gross Scope 1 GHG emissions"
    }
  ]
}
```

### CLI Runner

```bash
# Gap analysis via CLI
python cli.py gap-analysis <company_id>

# Output:
# 📊 Gap Analysis Results:
#    Total Required: 50
#    Complete: 12
#    Partial: 18
#    Missing: 20
#    Completion: 24.0%
#    Priority Actions:
#    🔴 [CRITICAL] Gross Scope 1 GHG emissions (tCO2e)
```

### Frontend Integration

La Gap Analysis è integrata nella pagina `assessment/page.tsx`:
- **Tab "Gap Analysis"** nel wizard assessment
- **Pulsante**: "Avvia Gap Analysis"
- **Metriche**: Total Required, Complete, Partial, Missing (card grid)
- **Progress bar**: completion percentage
- **Priority Actions**: lista con badge colore (critical=red, high=yellow, medium=gray)
- **Limit**: mostra prime 5 azioni prioritarie
